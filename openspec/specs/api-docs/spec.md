# api-docs Specification

## Purpose
Документация API сайта: схемы zod рядом с маршрутами `src/app/api`, документы OpenAPI 3.1 маршрутов и вызовов Supabase, интерактивная страница `/api/docs` с картой гео-ответов.

## Requirements

### Requirement: Схемы маршрутов
У каждого маршрута `src/app/api` SHALL быть схемы zod запроса и ответа в `schema.ts` рядом с ним. Маршрут SHALL разбирать запрос этими схемами, его ответ SHALL проверяться компилятором по схеме ответа, а схема — по доменному типу ответа.

#### Scenario: Схема разошлась с типом
- **WHEN** в тип `Hotel` добавлено поле, а в схему отеля — нет
- **THEN** `npm run typecheck` падает

### Requirement: Документ OpenAPI
Сайт SHALL отдавать `GET /api/openapi.json` — документ OpenAPI 3.1, сгенерированный из схем маршрутов, во всех окружениях (production, preview, development). Каждый метод каждого маршрута `src/app/api` SHALL быть описан с параметрами, телом, ответами и реальными примерами (отели Валенсии); сервер документа SHALL быть текущим окружением. Документ MUST NOT содержать значений ключей и секретов; `POST /api/revalidate` SHALL быть описан со схемой bearer без значения.

#### Scenario: Новый маршрут
- **WHEN** в `src/app/api` добавлен `route.ts` или метод без описания в документе
- **THEN** `npm test` падает и называет путь и метод

#### Scenario: Валидный документ
- **WHEN** документ сгенерирован
- **THEN** он проходит проверку структуры OpenAPI 3.1, все `$ref` разрешаются, примеры ответов проходят свои схемы

#### Scenario: Секреты
- **WHEN** разработчик открывает `/api/openapi.json`
- **THEN** в нём нет значений ключей service role, моделей и Supabase

### Requirement: Раздел Supabase
Сайт SHALL отдавать `GET /api/openapi/supabase.json` — OpenAPI 3.1 таблиц, представлений и функций Supabase, которые вызывает код `src`, со схемами из `database.types.ts` и файлами вызова. Раздел SHALL генерироваться скриптом без ключей; тест SHALL сверять его с `database.types.ts` и кодом.

#### Scenario: Новые типы базы
- **WHEN** `database.types.ts` или вызовы Supabase в `src` изменились без `npm run docs:supabase`
- **THEN** `npm test` падает

### Requirement: Страница документации
Страница `/api/docs` SHALL показывать интерактивную документацию обоих документов с выполнением запросов («Try it») против текущего окружения, во всех окружениях. Ответ гео-маршрута (отели, вид, здания, шум, карта Эвала) SHALL показываться на карте рядом с ответом; пример ответа гео-маршрута SHALL показываться на карте без запроса. Страница SHALL работать без горизонтального скролла на 375 и 1280 px.

#### Scenario: Try it с картой
- **WHEN** разработчик выполняет `GET /api/hotels/ota-9096882/noise-map` на `/api/docs`
- **THEN** рядом с ответом карта показывает полигоны шума вокруг отеля

#### Scenario: Пример на карте
- **WHEN** разработчик выбирает «Пример на карте» для вида из отеля
- **THEN** карта показывает отель, лучи и цели примера

### Requirement: Запуск инструмента в ответе ассистента
Схема `POST /api/assistant` SHALL описывать `chatId` и `messageId` запроса и компонент `ToolRun` в шагах ответа (id запуска и результат контракта с источниками, характеристиками, расчётами, ограничениями и ошибкой); пример ответа о шуме для ota-9096882 SHALL проходить проверку по схеме.

#### Scenario: Пример о шуме
- **WHEN** тест документа проверяет примеры
- **THEN** ответ о шуме с шагом «Анализ шума» и его `run` соответствует схеме

### Requirement: Знания об отеле в публичном API
Сайт SHALL отдавать хранилище знаний настоящего видимого отеля тремя маршрутами только для чтения с ключом anon и кэшем CDN: `GET /api/hotels/{hotelId}/claims?property=&limit=` (утверждения со значением, статусом, уверенностью, источниками и расчётом), `GET /api/hotels/{hotelId}/documents/search?q=&limit=` (фрагменты отзывов с рангом и источником) и `GET /api/hotels/{hotelId}/relations?predicate=&category=&limit=` (связи с местами: объект, координаты, расстояние с уверенностью, источник).

#### Scenario: Аптеки рядом
- **WHEN** клиент запрашивает `GET /api/hotels/ota-9096882/relations?predicate=near&category=pharmacy`
- **THEN** он получает аптеки по возрастанию расстояния, у каждой — координаты, расстояние в метрах с уверенностью и источник OSM

#### Scenario: Синтетический отель
- **WHEN** клиент запрашивает `claims` отеля генератора
- **THEN** ответ — 404 `{ error }`

### Requirement: Ошибки и размер ответа знаний об отеле
Вход трёх маршрутов SHALL проверяться схемой zod: недопустимый запрос — 400. Неизвестный, скрытый в окружении и синтетический отель SHALL давать 404, нечитаемое хранилище — 503, через `apiError`. Размер ответа SHALL ограничиваться `limit`, у `claims` и `relations` — с признаком `truncated`.

#### Scenario: Слишком большой предел
- **WHEN** клиент передаёт `limit=201`
- **THEN** ответ — 400

### Requirement: Поиск по отзывам без подмены запроса
Запрос поиска SHALL уходить в поиск без подмены. Описание операции SHALL говорить, что стеммер не сводит «шум» и «шумно», а отзывы — недоверенный текст гостей, который читают как данные.

#### Scenario: Запрос не расширяется
- **WHEN** клиент ищет «шум»
- **THEN** ответ содержит `query: "шум"`, а фрагменты со словом «шумно» не добавляются

### Requirement: Знания об отеле в документе OpenAPI
Три маршрута SHALL быть описаны в документе OpenAPI под тегом «Знания об отеле»: схемы из zod рядом с маршрутами, описание на русском, живые примеры ответов (ota-9096882, для отзывов ota-7857547 с запросом, который находит фрагменты). Страница `/api/docs` SHALL показывать места ответа `relations` на карте.

#### Scenario: Пример на карте
- **WHEN** разработчик открывает пример ответа `relations`
- **THEN** карта рисует места с названием и расстоянием и маркер отеля

### Requirement: Расчёт шума в документации
`/api/docs` SHALL описывать оценку шума у фасада noise-estimate-v1 в описаниях `GET /api/hotels/{hotelId}/claims` и `GET /api/hotels/{hotelId}/noise-map`: свойства `noise.estimate.*`, формулы, таблицу опорных уровней заведений, источники EEA, уверенность и ограничения — из тех же констант, что считает оценку. Примеры ответов `noise-map` и `claims` (в том числе `noise.estimate.street.` для ota-9741622) SHALL быть сняты с работающего сайта.

#### Scenario: Пример оценки
- **WHEN** разработчик открывает примеры ответа `getHotelClaims`
- **THEN** среди них пример ota-9741622 с `noise.estimate.street.lday` 65,2–73,2 дБ и его расчётом `noise-estimate-v1`
