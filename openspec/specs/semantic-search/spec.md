# semantic-search Specification

## Purpose
Поиск объектов каталога по смыслу текста: векторы `nemotron-3.5-embed-1b` в Supabase pgvector, реранжирование `nemotron-3.5-rerank-8b`; при недоступности моделей — прежние правила.

## Requirements

### Requirement: Векторы каталога
Отели каталога SHALL иметь векторы `nemotron-3.5-embed-1b` в Supabase pgvector. Скрипт загрузки SHALL пересчитывать только изменённые отели и отели с векторами другой модели и SHALL не создавать документов маршрутов; запись — только сервисным ключом. Поиск по смыслу SHALL искать только отели.

#### Scenario: Повторный запуск
- **WHEN** `db:embed` запускается второй раз без изменений каталога
- **THEN** новых запросов к модели нет

#### Scenario: Только отели
- **WHEN** выполняется `db:embed`
- **THEN** загружаются документы только вида `hotel`

#### Scenario: Смена модели
- **WHEN** векторы сделаны `nemotron-3.5-embed-1b`, а `db:embed` запускается с `nemotron-3.5-embed-1b`
- **THEN** векторы всех отелей пересчитываются новой моделью

### Requirement: Поиск по смыслу
Сервер SHALL находить объекты по тексту: ближайшие векторы, затем реранжирование `nemotron-3.5-rerank-8b`. Результат SHALL различать «найдено», «ничего не найдено» и сбой. При сбое или недоступности модели SHALL возвращаться прежний подбор по правилам без сообщения об ошибке; поиск похожих по фото SHALL сообщать «поиск не ответил» только при сбое.

#### Scenario: Смысловой запрос
- **WHEN** помощнику пишут «тихий хостел с быстрым Wi‑Fi в Праге»
- **THEN** первые варианты — хостелы Праги с Wi‑Fi не ниже 100 Мбит/с

#### Scenario: Модель недоступна
- **WHEN** модель эмбеддингов не ответила
- **THEN** помощник отвечает по прежним правилам

#### Scenario: Пусто — не сбой
- **WHEN** поиск похожих по фото ответил без совпадений
- **THEN** шаг завершается «похожих не нашёл», а не «поиск не ответил»

### Requirement: Общий запрос вектора
Одновременные поиски с одинаковым текстом SHALL делить один запрос вектора к модели. Отмена или таймаут одного поиска SHALL прерывать только этот поиск: остальные поиски с тем же текстом SHALL получить вектор и пройти по смыслу.

#### Scenario: Первый поиск отменён
- **WHEN** два поиска с одинаковым текстом идут одновременно и первый отменён до ответа модели
- **THEN** второй поиск получает вектор и возвращает результат по смыслу, а не по правилам

#### Scenario: Запрос модели не удался
- **WHEN** общий запрос вектора завершился ошибкой
- **THEN** вектор не кешируется, следующий поиск с тем же текстом запрашивает модель снова

### Requirement: Модели через API NVIDIA
Эмбеддинги, реранк и запасные модели SHALL идти через API NVIDIA с ключом `NVIDIA_API_KEY`. Текст SHALL обрабатывать цепочка `GigaChat-3-Ultra` (`GIGACHAT_AUTH_KEY`) → `nemotron-3.5-lightning` → `nemotron-3.5-bolt-e4b` → `minimax-m3.1-flash`, у каждой свой таймаут; без `GIGACHAT_AUTH_KEY` она начинается с `lightning`. Без ключей или ответа моделей SHALL работать запасной путь по правилам; во втором случае помощник SHALL предупреждать. Скрипты векторов SHALL держать лимит 40 запросов в минуту.

#### Scenario: Ключ есть
- **WHEN** задан `NVIDIA_API_KEY` и пользователь пишет помощнику
- **THEN** запрос уходит в API NVIDIA, ответ — по смыслу

#### Scenario: Нет ключа
- **WHEN** `NVIDIA_API_KEY` не задан
- **THEN** помощник и вайб работают по правилам без сообщения об ошибке

#### Scenario: Лимит
- **WHEN** `db:embed` получает ответ 429
- **THEN** скрипт ждёт и повторяет запрос, не теряя отели

#### Scenario: Запасная текстовая модель
- **WHEN** `nemotron-3.5-lightning` не ответила за свой таймаут
- **THEN** ответ даёт `nemotron-3.5-bolt-e4b` в пределах общего срока

#### Scenario: GigaChat не ответил
- **WHEN** `GigaChat-3-Ultra` вернул 429, 5xx, ответ не по схеме или не уложился в свой таймаут
- **THEN** ответ даёт `nemotron-3.5-lightning` в пределах общего срока

#### Scenario: Ни одна модель не ответила
- **WHEN** ключ задан, но ни одна модель текстовой цепочки не ответила
- **THEN** помощник отвечает по правилам, затем отдельным сообщением пишет «Модели сейчас недоступны, поэтому отвечаю по простым правилам. Попробуйте чуть позже — подберу точнее.»

### Requirement: GigaChat в текстовой цепочке
Запросы к GigaChat SHALL идти с токеном из `POST /api/v2/oauth` по ключу `GIGACHAT_AUTH_KEY`: токен кешируется на сервере, обновляется заранее и после 401. Сертификат НУЦ Минцифры SHALL подключаться только к запросам GigaChat, проверка TLS остальных запросов SHALL не меняться. Инструменты и схемы ответа SHALL уходить GigaChat как `functions`/`function_call`; ответ не по схеме SHALL отдавать запрос следующей модели цепочки.

#### Scenario: Токен кеширован
- **WHEN** два запроса к GigaChat идут подряд в пределах жизни токена
- **THEN** токен запрашивается один раз

#### Scenario: Токен отозван
- **WHEN** GigaChat отвечает 401
- **THEN** запрашивается новый токен и запрос повторяется один раз

#### Scenario: Ответ не по схеме
- **WHEN** GigaChat отвечает текстом вместо вызова функции схемы
- **THEN** запрос получает следующая модель цепочки

### Requirement: Время основной текстовой модели
Первая текстовая модель `GigaChat-3-Ultra` SHALL получать 4,5 с, следующая `nemotron-3.5-lightning` — 3,5 с, прежде чем запрос перейдёт к следующей модели цепочки. Общее окно текстовой цепочки SHALL быть 9 с, чтобы последняя модель цепочки получала время на ответ.

#### Scenario: Медленный ответ основной модели
- **WHEN** `GigaChat-3-Ultra` отвечает за 4 с
- **THEN** ответ берётся от неё, а не от `nemotron-3.5-lightning`

#### Scenario: Две модели зависли
- **WHEN** `GigaChat-3-Ultra` и `nemotron-3.5-lightning` не ответили за свои таймауты
- **THEN** запрос получает `nemotron-3.5-bolt-e4b` в пределах окна 9 с

### Requirement: Повтор поиска по смыслу без фото
Если поиск по смыслу в сообщении без фото не ответил или упал, Эвал SHALL повторить его один раз, когда до срока ответа хватает времени. Если не удался и повтор, Эвал SHALL подобрать отели по правилам и отдельным сообщением написать «Модели сейчас недоступны, поэтому отвечаю по простым правилам. Попробуйте чуть позже — подберу точнее.» Без ключа и при пустом результате SHALL обходиться без повтора и предупреждения.

#### Scenario: Повтор успел
- **WHEN** первый запрос к эмбеддингам завис, а повтор ответил
- **THEN** отели плана подобраны по смыслу, предупреждения нет, ответ пришёл не позже 15 секунд

#### Scenario: Повтор не удался
- **WHEN** обе попытки поиска по смыслу не ответили
- **THEN** отели подобраны по правилам, шаг поиска отмечен «модель не ответила — подобрал по правилам», а после ответа одно сообщение о недоступных моделях

#### Scenario: Ничего не нашлось
- **WHEN** поиск по смыслу ответил пустым результатом
- **THEN** повтора и предупреждения нет

### Requirement: Векторы фото отелей
Фото отелей Валенсии SHALL иметь векторы `nvidia/llama-nemotron-embed-vl-1b-v2` (2048 чисел) в таблице `hotel_photo_embeddings` с индексом HNSW по косинусу; таблица SHALL быть закрыта для `anon` и `authenticated`, запись — только сервисным ключом.

#### Scenario: Закрытая таблица
- **WHEN** `anon` читает `hotel_photo_embeddings`
- **THEN** доступа нет

### Requirement: Загрузка векторов фото
`npm run db:embed:photos` SHALL считать векторы пачками по 4 фото не чаще 40 запросов в минуту, пропускать фото без `url` и отвергнутые моделью (422), считать только фото без вектора этой модели (`content_hash`) и удалять векторы фото, которых нет в каталоге.

#### Scenario: Повторный запуск
- **WHEN** `npm run db:embed:photos` запускается второй раз без изменений каталога
- **THEN** в модель ничего не уходит

#### Scenario: Фото без адреса
- **WHEN** у фото отеля нет `url`
- **THEN** оно пропускается, остальные считаются

#### Scenario: Без ключа модели
- **WHEN** `npm run db:embed:photos` запускается без `NVIDIA_API_KEY`
- **THEN** скрипт завершается ошибкой, не меняя данных

### Requirement: Поиск отелей по фото
Сервер SHALL находить отели по вектору фото пользователя: ближайшие фото каталога, максимум сходства по отелю, лучшие отели в порядке убывания; с несколькими фото — максимум по отелю среди всех. Поиск SHALL идти только по Валенсии и показывать только отели, видимые в этой среде. Фото SHALL быть data URL WebP или JPEG в пределах `MAX_PHOTO_URL_LENGTH`; иное SHALL отвергаться без обращения к модели. Результат SHALL различать «найдено», «ничего не найдено» и сбой.

#### Scenario: Фото своего отеля
- **WHEN** пользователь присылает фото из номера отеля Валенсии, чьи другие фото есть в индексе
- **THEN** этот отель среди найденных

#### Scenario: Чужой формат
- **WHEN** фото не data URL WebP или JPEG
- **THEN** поиск по фото не вызывает модель и возвращает сбой
