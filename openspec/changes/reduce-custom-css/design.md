# Design

## Context

Визуальная миграция на примитивы shadcn выполняется в `migrate-composite-components`, задача 4.1. Этот change продолжает её для остальных стилей и `globals.css`. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Суммарный размер CSS сборки уменьшается; число замеров фиксируется до и после.
- Для каждого переведённого компонента визуал сохраняется в пределах допустимых отклонений.

**Non-Goals:**
- Удаление всех `*.module.css` в одном change.
- Изменение токенов дизайн-системы (это отдельный OpenSpec change дизайн-системы).

## Decisions

**Замер размера через сборку.** Метрика — суммарный размер файлов в `.next/static/css` после `npm run build`. Это проверяемо и не требует новых инструментов.

**Скриншоты до и после для пяти компонентов.** Сравнение ручное, по отклонениям. Автоматический визуальный diff — отдельное решение, если понадобится.

**Порядок компонентов из TODO:** `SearchPanel`, `RandomSearch`, `Header`, `SearchForm`, `AssistantSearch`. Каждый компонент — отдельный коммит.

## Risks / Trade-offs

- [Tailwind-классы в JSX станут длиннее] → Принято: это цена за отсутствие CSS-файла.
- [Потеря состояний `data-*` при переносе] → Проверять состояния (hover, focus, open) на скриншотах.

## Migration Plan

Компонент за компонентом, каждый коммит проходит сборку. Откат — возврат коммита компонента.
