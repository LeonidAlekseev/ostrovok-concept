# Design

## Context

Мотивация — в proposal.md (раздел Why). Текущее состояние, которое определяет подход:

- Стили: `src/app/globals.css` (токены, ресеты, `.visually-hidden`, reduced motion) и 11 CSS Modules. Tailwind, Base UI, `cn` и алиасов нет.
- Next 16 подключает Tailwind v4 через `@tailwindcss/postcss` и `@import 'tailwindcss'` в глобальном CSS (`node_modules/next/dist/docs/01-app/01-getting-started/11-css.md`). Порядок CSS в production определяется порядком импортов.
- shadcn CLI 4.22: `shadcn init -t next -b base`, флаги `--css-variables` (по умолчанию) и `--preset`. Компоненты кладутся в `@/components/ui`.
- Иконки уже на `lucide-react` — это библиотека иконок shadcn, замена не нужна.
- В `src/components/ui/` уже лежит `SmartImage`. Это нормальное соседство: в `ui/` живут все примитивы, и shadcn-, и свои.
- Тестов нет. Поведение зафиксировано в `openspec/specs/*`, визуал — в `references/homepage.jpg` и в текущей вёрстке.

## Goals / Non-Goals

**Goals:**
- Один источник цветов, радиусов, типографики и брейкпоинтов для Tailwind и CSS Modules одновременно.
- Примитивы shadcn с вариантами под бренд, на которые можно переводить компоненты по одному.
- Видимый фокус везде (см. `specs/design-system`).

**Non-Goals:**
- Тёмная тема. Блок `.dark`, который сгенерирует shadcn, удаляется.
- Перевод доменной графики (глобус, пины, карточка отеля на глобусе, слот-машина, конфетти, баннер) на Tailwind. Эти части только переходят на токены и шкалы.
- Составные виджеты на Base UI — это change `migrate-composite-components`.
- Пиксельное совпадение с текущим видом за пределами палитры: шкалы могут сдвинуть размеры на 1–2 px.

## Decisions

### D1. Три слоя токенов

```
brand (сырые значения)  -->  semantic (роли)  -->  @theme inline (Tailwind)
--brand-blue #0645e8         --primary               --color-primary
--brand-lime #a5e87b         --accent / --brand      --color-brand
...                          --ring, --border ...     ...
                                  |
                                  +--> CSS Modules: var(--primary), var(--muted-foreground)
--decor-* (конфетти, робот, барабан) --> только CSS Modules / inline SVG
```

Соответствие бренда и ролей:

| бренд | роль |
|---|---|
| `#0645e8` blue | `--primary`, `--ring`, `--secondary-foreground` |
| `#0538c4` blue-hover | `--primary-hover` (своё расширение) |
| `#e6eeff` blue-soft | `--secondary` |
| `#ffffff` white | `--primary-foreground`, `--card`, `--popover` |
| `#f2f4f7` page-bg | `--background` |
| `#101828` text | `--foreground`, `--card-foreground`, `--popover-foreground` |
| `#e8ecf2` gray-bg | `--muted` |
| `#667085` text-2 | `--muted-foreground` |
| `#dfe5ee` line | `--border`, `--input` |
| `#a5e87b` lime | `--brand` (фон hero и страницы, `theme-color`) |
| `#07162f` navy | `--brand-foreground`, `--accent-foreground` |
| `#4cc13a` / `#dcf7c4` green | `--success` / `--success-soft` |
| `#d92d20` danger | `--destructive` |

`--accent` (наведение в меню и списках shadcn) = `--secondary` (`#e6eeff`): лайм как фон наведения слишком громкий.

Прозрачные варианты (`rgba(7, 22, 47, 0.12)` в тенях и т.п.) строятся из бренда через `color-mix(in srgb, var(--brand-navy) 12%, transparent)`. Так 71 `rgba`-литерал сводится к токенам без новых значений. Тени — токены `--shadow-soft`, `--shadow-card`, `--shadow-popover`.

Альтернатива: оставить имена `--blue` и т.п. и добавить роли поверх. Отклонена: два имени у одного цвета в модулях ведут к дрейфу. Старые имена удаляются, модули переходят на роли.

### D2. Гибрид: кто чем стилизуется

- `src/components/ui/*` — только Tailwind-классы через `cn()` и `cva`.
- Доменные компоненты: свои модули. Внутри модулей — только `var(--роль)`, `var(--decor-*)` и шкалы.
- Один элемент стилизуется **либо** утилитами, **либо** модулем. Исключение — `className` из модуля на примитиве, но только для раскладки (`grid-area`, `margin`, `width`), не для цвета и состояний.

Каскад: Tailwind кладёт preflight, компоненты и утилиты в `@layer`, а CSS Modules остаются без слоя и поэтому побеждают любые слои. Это и нужно: раскладка из модуля переопределяет примитив без `!important`. Обратная сторона: `cn()` не видит модульные классы. Отсюда и правило «только раскладка».

### D3. Preflight включён

shadcn-примитивы рассчитаны на preflight (`border-style: solid`, `border-color: var(--border)`, сброс `button`). Существующие ресеты из `globals.css` переносятся в `@layer base`. Остальное (отступы `h1–h3`, `p`, `ul`) сбрасывает preflight. Модули, которые полагались на браузерные отступы, получают явные значения при визуальной сверке.

Альтернатива: только `tailwindcss/theme` + `utilities` без preflight. Отклонена: тогда каждый примитив shadcn придётся чинить вручную.

### D4. Фокус

Глобальное `:focus, :focus-visible { outline: none }` удаляется. В `@layer base`:
`:focus-visible { outline: 2px solid var(--ring); outline-offset: 2px }`. В примитивах — родной `focus-visible:ring-*` shadcn на `--ring`. Синий ring даёт контраст 4,77:1 на лайме, 6,3:1 на `--background`, 5,96:1 на `--secondary` и 6,94:1 на белом, то есть везде выше порога 3:1. На синих кнопках используется `outline-offset`, чтобы кольцо легло на фон, а не на кнопку. Модули, где фокус был спрятан намеренно (canvas глобуса), явно задают `outline: none` там, где элемент не интерактивен.

### D5. Шкалы

- **Радиусы:** `--radius: 12px`. Производные `sm 8`, `md 10`, `lg 12`, `xl 16`, `2xl 24`, плюс `full`. Это покрывает текущие 4–24 px и `999px`. Литералы 2/4/6 px становятся `sm` или убираются.
- **Типографика:** шкала Tailwind (12/14/16/18/20/24/30/36/48/60/72). Размеры 13 и 15 px сдвигаются к 12/14/16. Плавные заголовки на `clamp()` становятся именованными токенами `--text-display`, `--text-title`, `--text-heading`, по одному на роль: сейчас их около 12 разных.
- **Шрифты:** `--font-sans` = Onest Variable, `--font-hand` = Caveat (акцент «уголок»).
- **Отступы:** базовая единица Tailwind 4 px. Внутри модулей — `calc(var(--spacing) * n)`.
- **Брейкпоинты:** `xs 375`, `sm 640`, `md 768`, `lg 980`, `xl 1240`. `lg` переопределяется, потому что раскладка настроена под 980. `xl` = `--page-max`. Медиазапросы 374/479/519 сводятся к `xs`/`sm`.

В модулях брейкпоинты берутся из темы: `@reference` на `globals.css` плюс `@media (width >= --theme(--breakpoint-md))`.

Результат проверки (задача 4.1): основной вариант работает в `next dev` (Turbopack) и `next build`, `--theme()` в медиазапросе компилируется в `min-width` из `@theme`, а `@reference` не добавляет в бандл ни preflight, ни утилит. Одна поправка: `@tailwindcss/postcss` не знает алиас `@/` из `tsconfig.json` (`Can't resolve '@/app/globals.css'`), поэтому путь относительный: `@reference "../app/globals.css"` (глубина зависит от папки модуля). Запасной вариант с числами не нужен.

### D6. Инициализация shadcn

`npx shadcn@latest init -t next -b base` с CSS-переменными. Генерированный `globals.css` используется как каркас (`@import 'tailwindcss'`, `tw-animate-css`, `@theme inline`, `@layer base`). Его нейтральная палитра и блок `.dark` заменяются слоями из D1. `components.json`: `aliases.ui = @/components/ui`, `aliases.utils = @/lib/utils`, `iconLibrary = lucide`. В `tsconfig.json`: `"paths": { "@/*": ["./src/*"] }`. Существующие относительные импорты не переписываются массово, а меняются на `@/` только в затронутых файлах.

### D7. Набор примитивов и варианты

| Примитив | Варианты | Куда переходит |
|---|---|---|
| Button | `default` (primary), `secondary` (blue-soft), `ghost`, `outline`, `link`; размеры `sm`, `default`, `lg`, `icon`, `icon-sm`; `shape: pill` | «Найти отель», «Крутить барабан», `panelAction`, `popoverDone`, «Смотреть все», «Заново», «Изменить», «Поделиться», «Ещё раз», «Отправить», иконки шапки, степперы, стрелки календаря, «Очистить направление», чипы ассистента |
| Input / Textarea | — | имя игрока, запрос ассистенту; поле направления — только классы Input (combobox в change 2) |
| Label | — | подписи полей барабана; визуально скрытые подписи остаются `.visually-hidden` |
| Field (`FieldError`, `FieldLabel`) | — | ошибки ручной формы и анкеты барабана, с той же связкой `id`/`aria-describedby` |
| Badge | `secondary`, `destructive`, `success` | бейдж «Новый отель», рейтинг, «выше бюджета» |
| Card | — | панель шапки (оболочка), блок результатов поиска, билет барабана |

Кнопки остаются нативными `<button>` с прежними `type`, `aria-*` и обработчиками. Примитив меняет только классы. Пины глобуса, карточка отеля на глобусе, `DestinationCard`, дни календаря, пункты подсказок, знаки зодиака и вкладки остаются в модулях: они доменные или уходят в change 2. Видимый фокус они получают из D4.

## Risks / Trade-offs

- [Preflight меняет отступы и списки в модулях] → Перед началом снять скриншоты на 375/768/1280 px, после каждой группы сверять глазами по секциям.
- [Модульный класс без слоя случайно перебьёт цвет примитива] → Правило D2 «только раскладка»; на ревью grep по модулям, которые передают `className` в `ui/*`.
- [`--theme()` в медиазапросах CSS Modules не поддержится] → Запасной вариант из D5; решение фиксируется в первой задаче шкал.
- [Сдвиг шкалы шрифтов на 1–2 px ломает плотные места (карточка отеля на глобусе, слот-машина)] → У доменных компонентов разрешены собственные `clamp()`-токены; общий скриншот-пасс.
- [shadcn init перезапишет `globals.css` и потеряет ресеты] → Init выполняется отдельным коммитом, затем ручное слияние с прежним файлом по diff.
- [Видимый фокус «вылезет» на элементах, которые пользователи кликают мышью] → Только `:focus-visible`; у текстовых полей фокус и так виден.

## Migration Plan

Каждая группа задач — отдельный коммит. После каждой группы: `npm run typecheck`, `npm run lint`, `npm run build` и визуальная сверка. Откат — `git revert` коммита группы, данных и API change не касается. Порядок: инфраструктура → токены → шкалы → фокус → примитивы → перевод компонентов → финальная сверка по specs.
