## Why
Решение пользователя 2026-10-24: убрать или сократить тяжёлые тесты, ориентир — сборка Vercel и CI (GitHub Actions + Vercel). Полный прогон `npm test` на `dev` (`7f02ae2`) идёт около 200 с, из них 118 с — один файл `src/components/SearchResultsPage/SearchResultsPage.test.tsx` (71 тест, отдельные тесты 2–5 с). Под нагрузкой локальные прогоны падают по таймауту (разные тесты `SearchResultsPage`, `AssistantSearch`), CI при этом зелёный. Следующие по весу: `AssistantSearch.test.tsx` 10,6 с, `StarSearch.test.tsx` 9,6 с.

## What Changes
- `SearchResultsPage.test.tsx`: оставить тесты контрактов страницы (разбор адреса, выдача и счётчик, фильтры и сортировка, страницы, подборка, окно отеля открывается/закрывается), убрать дублирующие сценарии одного поведения и долгие пользовательские цепочки, которые проверяют то же, что unit-тесты `src/lib/*` (`results.ts`, `search.ts`). Тяжёлую подготовку (каталог, MapLibre-мок) делать один раз на файл; где ждём таймеры — фейковые таймеры вместо реального ожидания.
- `StarSearch.test.tsx` (ожидание 2,5 с), `AssistantSearch.test.tsx`: фейковые таймеры или более узкие тесты вместо реальных ожиданий.
- Поведение приложения не меняется; удаляемые тесты перечисляются в PR с причиной (что покрывает это поведение вместо них).
- Цель: полный `npm test` локально ≤ 90 с, ни один тест не дольше 1,5 с, три полных прогона подряд без падений; CI-шаг `npm test` быстрее прежнего.

## Impact
- Тесты `SearchResultsPage`, `StarSearch`, `AssistantSearch`; при необходимости `vitest.config.ts`. Код приложения и specs не меняются.
- После `selection-to-search` (тесты подборки уже в `dev`); до `assistant-chat-redesign` не обязателен.
