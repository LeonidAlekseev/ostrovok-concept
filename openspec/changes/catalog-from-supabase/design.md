## Решения

- **Граница.** Сервер: `src/lib/db/catalog.ts` с функциями того же смысла, что `catalogSource` (`loadDestinations`, `loadHotelSummaries`, `loadHotel`, `loadHotels(ids)`, `loadCityHotels`, `loadNewHotels`), но асинхронными. Клиент: данные пропсами от серверной страницы или `GET /api/hotels?ids=`. Синхронный `catalogSource` в клиенте исчезает.
- **Объём.** Сводка отеля (`HotelSummary`) хранится в колонках/`data`; полный отель — `data jsonb`. Читать только нужные колонки: списки и карты — сводки; страница отеля — один полный отель. Не отдавать клиенту весь каталог (~1,9 МБ).
- **Кеш.** Кеш Next 16 (прочитать `node_modules/next/dist/docs/` про `use cache`/`cacheTag`/`cacheLife` или `unstable_cache` — что поддерживает текущая конфигурация) с тегом `catalog`. Страницы отелей остаются быстрыми: пререндер известных `id` при сборке + выдача новых по запросу.
- **Сборка.** На Vercel ключи расшифровываются в `prebuild` (`.env.production.local`), база доступна при сборке. CI сборку не запускает. Локальная сборка без ключей — понятное сообщение «нет SUPABASE_URL: npm run secrets:reveal».
- **Тесты.** Тесты не ходят в сеть: слой данных мокается генератором (`buildCatalog()`), один набор фикстур.
- **Безопасность.** Чтение — anon-ключом под RLS; сервисный ключ только в `db:seed` и ревалидации.
