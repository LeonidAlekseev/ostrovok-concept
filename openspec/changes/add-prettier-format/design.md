# Design

## Context

Конфиг Prettier уже лежит в репозитории, поэтому правила стиля не выбираются заново. Нужно подключить его к проекту: зависимость и скрипты. Линтер проекта — `oxlint`; он не отвечает за форматирование и с Prettier не конфликтует. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- `npm run format:check` падает, если файлы не отформатированы.

**Non-Goals:**
- Изменение правил форматирования.
- Подключение Prettier в pre-commit hook (отдельное решение).

## Decisions

**Существующий конфиг Prettier без изменений.** Альтернатива — новый конфиг с нуля отвергнута: она меняла бы стиль, который уже задан в репозитории.

**Отдельный коммит форматирования.** Так `git blame` и ревью функциональных изменений не засоряются переформатированием.

## Risks / Trade-offs
