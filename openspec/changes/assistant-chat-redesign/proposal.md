## Why
Решение пользователя 2026-10-24: на отдельной странице `/assistant` (`search-entry-pages`) чат с Эвал должен быть удобным для долгих диалогов, а Эвал — подбирать отель по высоте здания и этажу, виду из окна, шуму и другим свойствам. Сейчас чат рассчитан на короткий обмен в панели главной (`AssistantSearch.tsx`), а данные о высоте и шуме (`hotel_geo`, #166) приложение не читает.

## What Changes
- **Чат на всю страницу:** лента сообщений с прокруткой и автопрокруткой к новому сообщению (без прыжков при чтении старых), поле ввода закреплено внизу, многострочный ввод (Enter — отправить, Shift+Enter — перенос), индикатор ответа, повтор при ошибке, «Новый диалог». Карточки отелей в ответах — `HotelTile` со ссылкой на отель. Удобно на 360 px (клавиатура телефона не закрывает поле) и на 1440 px (ограниченная ширина ленты).
- **История чатов** (решение пользователя 2026-10-24): пользователь ищет в нескольких сессиях, поэтому чатов несколько — список чатов с названием и датой, «Новый чат», переход к старому чату с его историей и условиями. Вошедший пользователь хранит чаты в Supabase (таблицы с RLS «только свои», связаны с `auth.users`), гость — в браузере, как сейчас; при входе чаты гостя переносятся в аккаунт.
- **Долгий диалог:** уточнения учитывают прежние условия чата («а повыше?», «а потише?»). В модель уходит ограниченный контекст: последние сообщения и сводка условий чата, чтобы не упираться в лимит модели.
- **Модель сообщений с ролями.** Сообщение чата имеет роль и статус, а не только «пользователь/Эвал». В будущем появится агент, который уточняет у владельцев отелей номера, условия и вид из окна; пользователь видит в чате, что написано владельцу, и ждёт ответа. В этом change агент не делается, но схема хранения и ленты не должна мешать добавить сообщения «Эвал → владелец отеля» и «ответ владельца» со статусом ожидания.
- **Новые критерии подбора.** Данные есть только по Валенсии (настоящие отели Островка):
  - высота здания и число этажей — из `hotel_geo` (`geo_buildings`);
  - шум днём и ночью — из `hotel_geo` (`geo_noise`, Lden/Lnight);
  - вид из окна — по названиям номеров и тексту отзывов/комментариев в данных Островка (`ota_hotels`). Вид относится к номеру, а не к отелю: не у всех номеров отеля есть вид. Эвал называет номера с видом и помечает, что это «по описанию».
- **Хранение без дублирования** (решения пользователя 2026-10-24, 5а): рассчитанные свойства — в таблицах Supabase, связанных внешним ключом с `public.hotels` (свойства отеля) и с номером отеля (вид из номера). Сырые данные `ota_hotels` и геоданные не копируются: в таблицах только выведенные значения и ссылка на источник. Расчёт — скриптом загрузки, повторный запуск идемпотентен. В описание отеля для поиска по смыслу (`hotelDocument`) добавляются эти свойства.
- **Нет данных — не придумывать.** Для отелей без данных Эвал говорит «нет данных». Синтетические данные для Валенсии в production не генерируются. Если для критерия не хватает данных, исполнитель останавливается и передаёт оркестратору список нужных данных (что, по каким отелям, в каком виде) — оркестратор запрашивает их у пользователя.
- **Ответ с объяснением:** у каждого предложенного отеля — почему он подходит под условия (например, «12 этажей», «тихо ночью: 45–49 дБ», «номера с видом на море»).
- Без модели (лимит или ошибка) — прежний запасной путь по правилам.
