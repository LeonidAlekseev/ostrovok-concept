## Why

Решения 98а, 100а, 101б и 105а: главная должна вести к готовым маршрутам, а не к ручному поиску отелей. В базе 12 маршрутов, по 3 на персону в разных городах (#129), и их эмбеддинги (`semantic-search`, #128). Главная их пока не показывает: на глобусе пины направлений и карточка нового отеля, ниже подборки отелей и ручная форма.

## What Changes

- **Карусель персон `#personas`** вместо «Популярных направлений»: 4 персоны («Студент», «Люкс», «Воркейшн», «Культура», подписи из `PERSONA_LABEL`). У выбранной персоны 2–3 маршрута в разных городах; переключатель городов показывает маршрут выбранного города. Карточка маршрута — общий компонент `RouteCard`: обложка (заглушка-градиент по `cover.tone`, пока нет фото), название, автор, город, ночи, «≈ N ₽ за K ночей» (та же оценка, что на `/routes/<id>`), ссылка на `/routes/<id>`.
- **Витрина маршрутов `#routes`**: все маршруты сеткой карточек `RouteCard`, сначала `featured`.
- **Глобус — только маршруты (100а)**: пины направлений заменяются пинами городов, где есть маршруты. Пин открывает карточку маршрута на глобусе (название, автор, город, цена); при нескольких маршрутах в городе — список. Карточка нового отеля заменяется сменяющейся карточкой маршрута у города-хаба (тот же ритм 5 с / 8 с при reduced motion, дуги сохраняются). Клик по карточке — переход на `/routes/<id>`.
- **Подборки отелей убраны (101б)**: `HomeCollections`, `src/lib/collections.ts` и их тесты удаляются, если больше нигде не используются.
- **Ручная форма только на `/search`**: на главной панель поиска — только ассистент, без вкладок. На `/search` сверху ручная форма (направление, даты, гости), заполненная из адреса; отправка обновляет выдачу. Состояние формы — существующий `useHotelSearch`.
- **Вайб, помощник и астро выдают лучший готовый маршрут (105а)**: над текущим итогом — карточка «Готовый маршрут» (`RouteCard`). Выбор — `semanticSearch(kind: 'route')` по тексту ответов; без поиска по смыслу (нет ключа, нет векторов, ошибка, таймаут) — правила: персона по ответам и город первого варианта итога, затем любой маршрут персоны. Маршрут есть всегда, если в базе есть маршруты; без маршрутов карточки нет. Время ответа не растёт: поиск маршрута идёт параллельно с подбором отелей и укладывается в существующие лимиты (помощник 14 с).
- **Данные**: серверный `loadRouteCards()` в `src/lib/db/routes.ts` — краткие карточки всех маршрутов (id, persona, destination, title, author, nights, оценка цены, cover, featured) под кешем с `ROUTES_TAG`; в браузер уходят только карточки.
