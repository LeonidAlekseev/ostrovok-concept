## Context

Чаты: `src/lib/assistantChats.ts` (`localStorage` у гостя), `src/lib/assistantChatsRemote.ts` (`assistant_chats`, `assistant_messages` у вошедшего; `anon` к ним доступа нет). Поиск по смыслу — `src/lib/ai/semantic.ts` (эмбеддинги текстов каталога). Модель текста — `ASSISTANT_MODEL` в `src/lib/ai/model.ts`, провайдер NVIDIA (`src/lib/ai/nvidia.ts`). Supabase Storage в проекте пока не используется.

## Goals / Non-Goals

**Goals:** фото как вход для поиска похожих и для уточнения запроса; хранение рядом с чатом; гость тоже может приложить фото, предупреждённый, что сохранится чат только после входа.

**Non-Goals:** эмбеддинги изображений каталога, вложения на странице отеля, файлы кроме изображений.

## Decisions

1. **Фото на сервер — в теле запроса** (оптимизированный WebP base64), а не по пути в Storage: так работает и у гостя, и сервер не читает Storage от имени пользователя. Storage — только для истории.
2. **Оптимизация в браузере** (`canvas` → WebP, 1600 px, качество 0,8; превью 320 px), `src/lib/imageOptimize.ts`. Без серверных зависимостей вроде `sharp`.
3. **Намерение:** модель текста по сообщению определяет `similar | refine | unclear`; при `unclear` или пустом тексте — вопрос с двумя чипами (`Question` с id `photo`). Выбор чипа повторяет запрос с тем же фото из сообщения.
4. **Похожие отели через описание:** `describePhoto` (VL) → текст → `semantic` поиск → карточки, подпись «Похоже: …». Альтернатива — эмбеддинги изображений — отклонена: новая таблица, скрипт по всем фото, иная модель.
5. **Учесть в запросе:** VL возвращает признаки по схеме (вид, вода, бассейн, стиль, город, если узнаваем); они идут в `wish` и разбор как текст пользователя с пометкой «по фото».
6. **Storage:** bucket `assistant-attachments` (private), политики `storage.objects` по первому сегменту пути = `auth.uid()`. `MessageData.attachments: { path?: string, preview: string, width, height }[]`; `preview` — data URL 320 px только у гостя, у вошедшего после загрузки удаляется, показ по `createSignedUrl`. Перенос гостевых чатов при входе загружает превью как фото (полное фото у гостя не хранится).
7. **Снимок «Поделиться»** (решение 4б): при создании снимка фото копируются (`storage.copy`) в публичный bucket `assistant-shared-attachments` по пути `<user_id>/<share_id>/<n>.webp`; в снимке — публичные ссылки. Копия, а не ссылка на приватный файл: удаление чата не ломает снимок, приватный bucket остаётся закрытым. Запись — только владельцем в свою папку.
8. **VL-модель** — `VISION_MODEL = 'nvidia/nemotron-3.5-super-vl-120b-a12b'`, таймаут 12 с, свой счётчик в `rateLimit`.

## Risks / Trade-offs

- Размер `localStorage` у гостя: превью ~15 КБ × 4 × 30 чатов ≈ 1,8 МБ → при переполнении старые превью отбрасываются, сообщение остаётся с подписью «Фото».
- Качество «похожих» через описание не проверено → после слияния отдельная проверка на реальных фото (TODO); при плохом результате — change на эмбеддинги по фото каталога.
- Снимок с фото публичен по ссылке → пользователь сам нажимает «Поделиться»; ссылка неугадываемая (uuid).
- Модель может не узнать место → ответ честно говорит, что увидела, без выдумки города.
- Удаление файлов не каскадное → удаление чата сначала удаляет объекты Storage, ошибка удаления не блокирует удаление чата и логируется.
