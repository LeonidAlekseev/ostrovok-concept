## Why

«Найти похожие отели» по фото искало по тексту: модель фото описывала снимок словами, поиск по смыслу брал отели по
описанию. На 12 тестовых фото свой отель не нашёл ни один (0 из 12). Модель `nvidia/llama-nemotron-embed-vl-1b-v2`
кладёт фото и текст в общее пространство (2048 чисел): замер на фото каталога Валенсии (фото из индекса против другого
фото того же отеля) — 120 отелей × 3 фото в индексе: top-1 42 %, top-5 58 %; 30 отелей × 4 фото: top-1 53 %, top-5
82 %. `nvidia/nemotron-3.5-embed-1b` принимает фото, но хуже (25 % и 39 % на 120 отелях); `nvidia/nvclip` для нашего
ключа недоступна (404). Решение пользователя 1а: берём `llama-nemotron-embed-vl-1b-v2`; только Валенсия (4а).

## What Changes

- Таблица `hotel_photo_embeddings` (`halfvec(2048)`, HNSW по косинусу, RLS без доступа ролям клиента) и функция
  `match_hotel_photos`: ближайшие фото, максимум по отелю.
- Серверный клиент модели `src/lib/ai/photoEmbedding.ts` (`server-only`, ключ NVIDIA только на сервере).
- Скрипт `npm run db:embed:photos` (`scripts/embed-photos.ts`): векторы фото отелей Валенсии, пачки по 4, 40 запросов
  в минуту, фото без `url` и ответ 422 пропускаются, повторный запуск считает только новые фото (`content_hash`).
- «Найти похожие отели» ищет по вектору фото пользователя (максимум косинуса по отелю, top-N). Фото пользователя —
  недоверенный ввод: тип и размер проверяются. Если в брифе город не Валенсия, вектора фото нет, поиск не ответил или
  ничего не нашёл — прежний поиск по описанию фото.
