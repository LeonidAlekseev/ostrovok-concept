## ADDED Requirements

### Requirement: Векторы фото отелей
Фото отелей Валенсии SHALL иметь векторы `nvidia/llama-nemotron-embed-vl-1b-v2` (2048 чисел) в таблице `hotel_photo_embeddings` с индексом HNSW по косинусу; таблица SHALL быть закрыта для `anon` и `authenticated`, запись — только сервисным ключом.

#### Scenario: Закрытая таблица
- **WHEN** `anon` читает `hotel_photo_embeddings`
- **THEN** доступа нет

### Requirement: Загрузка векторов фото
`npm run db:embed:photos` SHALL считать векторы пачками по 4 фото не чаще 40 запросов в минуту, пропускать фото без `url` и отвергнутые моделью (422), считать только фото без вектора этой модели (`content_hash`) и удалять векторы фото, которых нет в каталоге.

#### Scenario: Повторный запуск
- **WHEN** `npm run db:embed:photos` запускается второй раз без изменений каталога
- **THEN** в модель ничего не уходит

#### Scenario: Фото без адреса
- **WHEN** у фото отеля нет `url`
- **THEN** оно пропускается, остальные считаются

#### Scenario: Без ключа модели
- **WHEN** `npm run db:embed:photos` запускается без `NVIDIA_API_KEY`
- **THEN** скрипт завершается ошибкой, не меняя данных

### Requirement: Поиск отелей по фото
Сервер SHALL находить отели по вектору фото пользователя: ближайшие фото каталога, максимум сходства по отелю, лучшие отели в порядке убывания; с несколькими фото — максимум по отелю среди всех. Поиск SHALL идти только по Валенсии и показывать только отели, видимые в этой среде. Фото SHALL быть data URL WebP или JPEG в пределах `MAX_PHOTO_URL_LENGTH`; иное SHALL отвергаться без обращения к модели. Результат SHALL различать «найдено», «ничего не найдено» и сбой.

#### Scenario: Фото своего отеля
- **WHEN** пользователь присылает фото из номера отеля Валенсии, чьи другие фото есть в индексе
- **THEN** этот отель среди найденных

#### Scenario: Чужой формат
- **WHEN** фото не data URL WebP или JPEG
- **THEN** поиск по фото не вызывает модель и возвращает сбой
