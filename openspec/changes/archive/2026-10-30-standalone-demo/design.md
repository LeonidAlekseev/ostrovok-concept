## Context

Сайт читал Supabase через supabase-js в ~30 модулях и вызывал PostGIS-функции. Без базы данные нужно вшить в сборку, не переписывая компоненты.

## Decisions

- **Тот же интерфейс.** Клиенты Supabase заменены standalone-клиентом с теми же `from`/`rpc`/`auth`/`channel`; читатели и компоненты не менялись. Альтернатива — переписать читатели — отвергнута: больше кода и расхождение с `dev`.
- **Записанные ответы PostGIS.** Ответы функций с точкой отеля записаны при обходе локального `next dev` полной версии за прокси, который пропускает только GET и белый список `stable`-функций. Ключ — имя и аргументы (`callKey`). Поэтому вид, шум и цены совпадают с полной версией точно. Функции с произвольными аргументами (места OSM, поиск, векторы) — на JS.
- **Записи в браузере.** Снимок неизменен; `Db` накладывает строки браузера по первичному ключу. Сервер ничего не хранит: браузер присылает строки в теле (GET — знания в заголовке), маршрут возвращает изменения после тела, `after` дожидается до конца ответа. Кэш каталога обходится, если в запросе есть строки браузера.
- **Карты** — статические сжатые тайлы, упрощённые до ~1,5 м без потери фигур; маршрут собирает карту с CDN своего домена.

## Risks

- Записи живут в одном браузере: другой браузер их не видит, сервер-рендер страниц показывает только снимок.
- `checkViewPoints` для мест, не записанных при обходе, отвечает «нет данных»; места из Overpass не кэшируются.
- `ts_rank` приближён; латинские слова не стеммятся.
