# Design

## Context

Next.js 16: `/booking` и `/booking/confirmation` пререндерятся статически, параметры читаются на клиенте внутри Suspense. Перед кодом читать `node_modules/next/dist/docs/`. Поля и валидация — на примитивах `src/components/ui/*` (`field`, `input`, `textarea`, `radio-group`); недостающие примитивы добавлять через `npx shadcn@latest add`.

## Goals / Non-Goals

**Goals:**
- Полный путь от предложения до подтверждения с проверкой формы и сохранением бронирования.

**Non-Goals:**
- Реальная оплата, отправка данных на сервер, письма.
- Изменение и отмена бронирования (change `add-account-pages`).

## Decisions

**Гости:** для каждого номера — имя и фамилия основного гостя (обязательные). **Контакты:** email и телефон (обязательные, формат проверяется). **Пожелания** — необязательный текст до 500 символов.

**Карта:** номер 16–19 цифр с пробелами, проверка Luhn; срок `MM/YY` не в прошлом; CVC 3–4 цифры; имя держателя. Поля карты — `autocomplete="cc-number"` и т. п. Значения карты живут только в состоянии формы; в хранилище попадают последние 4 цифры. Демо-подсказка: тестовая карта `4242 4242 4242 4242`.

**Отправка:** все ошибки показываются у полей, фокус переходит на первое невалидное поле. Валидная форма — «Обрабатываем…» ~1 с, затем бронирование: номер `OS-` + 6 символов `[A-Z0-9]`, дата создания, предложение, гости, контакты, пожелания, способ оплаты и последние 4 цифры, сумма, условия отмены, статус `confirmed`. Переход `router.replace('/booking/confirmation?id=…')`, чтобы «Назад» не возвращал к отправленной форме.

**Ошибочное предложение** (разбор вернул ошибку) — «Предложение не найдено» со ссылкой на поиск. **Неизвестный номер** на подтверждении — «Бронирование не найдено» со ссылкой «Мои поездки».

## Risks / Trade-offs

- [Пользователь вводит настоящую карту] → Явная демо-пометка над формой; данные не сохраняются и не отправляются.
- [Бронирования только в этом браузере] → Принято для прототипа; пометка на подтверждении.

## Decisions (реализация)

- Проверки и создание бронирования — `src/lib/booking.ts`; поля формы — `src/components/BookingFields` (`TextField`, `GuestsFields`, `ContactFields`, `RequestsField`, `CardFields`). Они не знают о странице: значения, `onChange` и ошибки по id поля приходят снаружи, поэтому `add-account-pages` редактирует гостей, контакты и пожелания теми же компонентами и `validateTravelerDetails`.
- Ключ ошибки — id поля (`guest-<номер>-firstName`, `email`, `card-number`…); ошибки строятся в порядке полей на странице, фокус идёт на первый ключ. Чекбокс согласия фокусируется через видимый `role=checkbox` (id Base UI висит на скрытом input).
- Предзаполнение из сессии: имя делится по первому пробелу на имя и фамилию основного гостя первого номера; пока поле не тронуто, показывается значение сессии (состояние хранит только введённое пользователем).
- Если срок бесплатной отмены к моменту брони уже прошёл, в бронирование пишется «невозвратный» (как на странице тарифов); `cancellationDeadline` и `freeCancellationUntil` принимают `Pick<Rate, 'cancellation'>`, чтобы работать и с условиями, сохранёнными в бронировании.
- Подтверждение ждёт гидрации (`useHydrated`), иначе при пререндере мигало бы «Бронирование не найдено». Номер бронирования не совпадает с существующим (повторная генерация).
- Ссылка с ошибки предложения — «Найти отель» (`/#search`), пока нет `/search` (как на 404).
- Срок карты `MM/YY` действителен до конца указанного месяца; формат номера и срока выставляется при вводе, CVC — только цифры.
