## Why

Решения 98а, 99а и 104: витрине главной (`home-personas`) и ответам помощника, вайба и астро нужны готовые маршруты — 2–3 на персону в разных городах. Сейчас в базе один маршрут `prague-culture`.

## What Changes

- Скрипт `npm run routes:generate` (разовый, не в сборке): для каждой из 4 персон (`student`, `luxury`, `workation`, `culture`) 3 маршрута в разных городах каталога, всего ~12. Модель `nvidia/nemotron-3.5-lightning:free` (`generateObject` AI SDK, схема zod = модель `Route`) получает персону, город и список отелей города (id, тип, цена, удобства, вайб) и возвращает маршрут.
- Авторы: половина — вымышленные люди (`author: { kind: 'person', name }`, разные имена), половина — «Редакция О!Погнали» (`kind: 'editor'`).
- Проверка каждого маршрута через `parseRoute`: id отелей есть в каталоге, `transfers.length === stops.length + 1`, дни досуга в пределах ночей, цены > 0. Невалидный ответ — повтор (до 3), затем пропуск с сообщением.
- Недостающие отели (99а): если в городе нет подходящего объекта для персоны (например, вилла для `luxury`, рабочее место для `workation`), модель предлагает объект; он проходит ту же схему, что и сгенерированные отели, и попадает в `src/data/extraHotels.json`; сид добавляет такие объекты в каталог.
- Результат коммитится: `src/data/routes.ts` (или JSON рядом) — ~12 маршрутов вместо одного; повторный запуск детерминирован только по входу, поэтому результат проверяется глазами и коммитится, а не генерируется в сборке.
- После генерации: `npm run db:seed` (маршруты и доп. отели в демо-базу), `npm run db:embed`, если change `semantic-search` уже в `dev`.

## Impact

`scripts/generate-routes.ts`, `package.json`, `src/data/routes.ts`, `src/data/extraHotels.json`, `scripts/seed.ts`, тесты данных (`src/data/routes.test.ts`: все маршруты проходят `parseRoute`, по 3 на персону, города разные внутри персоны, авторы 50/50). Дельта спеки `routes`.
