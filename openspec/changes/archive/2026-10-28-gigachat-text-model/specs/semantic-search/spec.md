## MODIFIED Requirements

### Requirement: Модели через API NVIDIA
Эмбеддинги, реранк и запасные модели SHALL идти через API NVIDIA с ключом `NVIDIA_API_KEY`. Текст SHALL обрабатывать цепочка `GigaChat-3-Ultra` (`GIGACHAT_AUTH_KEY`) → `nemotron-3.5-lightning` → `nemotron-3.5-bolt-e4b` → `minimax-m3.1-flash`, у каждой свой таймаут; без `GIGACHAT_AUTH_KEY` она начинается с `lightning`. Без ключей или ответа моделей SHALL работать запасной путь по правилам; во втором случае помощник SHALL предупреждать. Скрипты векторов SHALL держать лимит 40 запросов в минуту.

#### Scenario: Ключ есть
- **WHEN** задан `NVIDIA_API_KEY` и пользователь пишет помощнику
- **THEN** запрос уходит в API NVIDIA, ответ — по смыслу

#### Scenario: Нет ключа
- **WHEN** `NVIDIA_API_KEY` не задан
- **THEN** помощник и вайб работают по правилам без сообщения об ошибке

#### Scenario: Лимит
- **WHEN** `db:embed` получает ответ 429
- **THEN** скрипт ждёт и повторяет запрос, не теряя отели

#### Scenario: Запасная текстовая модель
- **WHEN** `nemotron-3.5-lightning` не ответила за свой таймаут
- **THEN** ответ даёт `nemotron-3.5-bolt-e4b` в пределах общего срока

#### Scenario: GigaChat не ответил
- **WHEN** `GigaChat-3-Ultra` вернул 429, 5xx, ответ не по схеме или не уложился в свой таймаут
- **THEN** ответ даёт `nemotron-3.5-lightning` в пределах общего срока

#### Scenario: Ни одна модель не ответила
- **WHEN** ключ задан, но ни одна модель текстовой цепочки не ответила
- **THEN** помощник отвечает по правилам, затем отдельным сообщением пишет «Модели сейчас недоступны, поэтому отвечаю по простым правилам. Попробуйте чуть позже — подберу точнее.»

### Requirement: GigaChat в текстовой цепочке
Запросы к GigaChat SHALL идти с токеном из `POST /api/v2/oauth` по ключу `GIGACHAT_AUTH_KEY`: токен кешируется на сервере, обновляется заранее и после 401. Сертификат НУЦ Минцифры SHALL подключаться только к запросам GigaChat, проверка TLS остальных запросов SHALL не меняться. Инструменты и схемы ответа SHALL уходить GigaChat как `functions`/`function_call`; ответ не по схеме SHALL отдавать запрос следующей модели цепочки.

#### Scenario: Токен кеширован
- **WHEN** два запроса к GigaChat идут подряд в пределах жизни токена
- **THEN** токен запрашивается один раз

#### Scenario: Токен отозван
- **WHEN** GigaChat отвечает 401
- **THEN** запрашивается новый токен и запрос повторяется один раз

#### Scenario: Ответ не по схеме
- **WHEN** GigaChat отвечает текстом вместо вызова функции схемы
- **THEN** запрос получает следующая модель цепочки

### Requirement: Время основной текстовой модели
Первая текстовая модель `GigaChat-3-Ultra` SHALL получать 4,5 с, следующая `nemotron-3.5-lightning` — 3,5 с, прежде чем запрос перейдёт к следующей модели цепочки. Общее окно текстовой цепочки SHALL быть 9 с, чтобы последняя модель цепочки получала время на ответ.

#### Scenario: Медленный ответ основной модели
- **WHEN** `GigaChat-3-Ultra` отвечает за 4 с
- **THEN** ответ берётся от неё, а не от `nemotron-3.5-lightning`

#### Scenario: Две модели зависли
- **WHEN** `GigaChat-3-Ultra` и `nemotron-3.5-lightning` не ответили за свои таймауты
- **THEN** запрос получает `nemotron-3.5-bolt-e4b` в пределах окна 9 с
