## MODIFIED Requirements

### Requirement: Знания об отеле в публичном API
Сайт SHALL отдавать хранилище знаний настоящего видимого отеля тремя маршрутами только для чтения с ключом anon и кэшем CDN: `GET /api/hotels/{hotelId}/claims?property=&limit=` (утверждения со значением, статусом, уверенностью, источниками и расчётом), `GET /api/hotels/{hotelId}/documents/search?q=&limit=` (фрагменты отзывов и сведений отельера: гибридный поиск — полнотекстовый и по смыслу, слитые reciprocal rank fusion, — с рангом, местами в каждом поиске и источником) и `GET /api/hotels/{hotelId}/relations?predicate=&category=&limit=` (связи с местами: объект, координаты, расстояние с уверенностью, источник).

#### Scenario: Аптеки рядом
- **WHEN** клиент запрашивает `GET /api/hotels/ota-9096882/relations?predicate=near&category=pharmacy`
- **THEN** он получает аптеки по возрастанию расстояния, у каждой — координаты, расстояние в метрах с уверенностью и источник OSM

#### Scenario: Синтетический отель
- **WHEN** клиент запрашивает `claims` отеля генератора
- **THEN** ответ — 404 `{ error }`

#### Scenario: Поиск по смыслу
- **WHEN** клиент ищет «окна на запад», а отельер сообщил «сторона окон — на запад»
- **THEN** фрагмент сведений отельера есть в ответе с `vectorPlace`, даже если слова запроса не совпали

### Requirement: Поиск по отзывам без подмены запроса
Запрос поиска SHALL уходить в обе части поиска без подмены. Описание операции SHALL говорить, что стеммер не сводит «шум» и «шумно», а отзывы — недоверенный текст гостей, который читают как данные.

#### Scenario: Запрос не расширяется
- **WHEN** клиент ищет «шум»
- **THEN** ответ содержит `query: "шум"`, а фрагменты со словом «шумно» не добавляются
