## Why

Пакет 4 «noise-view-accuracy» из TODO: оценка шума `noise-estimate-v1` завышала шум во дворе и мерила расстояние до заведений от точки отеля; эвал и векторы не говорили, что высота здания — оценка модели; правило сомнительного здания не ловило «1 этаж, ≈17 м»; парки-relation хранились только центром.

## What Changes

- `noise-estimate-v2`: заведения не прибавляются к окнам во двор (здание их экранирует); расстояние до заведений — от стены здания отеля (контур EUBUCCO), без здания — от точки. Новая функция БД `osm_places_near_facade`; её расстояния используются и для связей `near`.
- Описание расчёта в `/api/docs` и «Как мы считаем» отражает v2.
- Высота и этажность, оценённые моделью EUBUCCO, в причинах Эвала и в тексте для векторов называются «≈N м (по оценке модели, A–B м)».
- Сомнительное здание: больше 8 м на этаж (кадастровая этажность с высотой модели) тоже сомнительно.
- `scripts/osm-pbf-to-overpass.py` отдаёт границу парков и пляжей-relation (pyosmium, `polygons`); загрузчик хранит её `MULTIPOLYGON`.

## Impact

- Миграция `20261029100000_osm_places_near_facade.sql` (новая функция, ничего не меняет в данных).
- После слияния: применить миграцию, `npm run db:osm-places` с новой выгрузкой (границы парков), `npm run db:features`, `npm run db:embed`, `npm run docs:supabase`, `npm run docs:examples`.
