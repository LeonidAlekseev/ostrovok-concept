## Why

Пользователь просит подобрать отель по тому, что знает хранилище: «чтобы рядом была аптека и было тихо ночью». Подбор сейчас идёт по смыслу и по `hotel_features`, а характеристики хранилища (claims с уверенностью, связи `near`, фрагменты отзывов) видны только в чате одного отеля через «Анализ шума». Эвал не умеет сам выбирать инструменты подбора, не показывает, по каким характеристикам и с какой уверенностью выбраны отели, и не отвечает аргументированно по этим данным.

## What Changes

- Три инструмента контракта `ToolResult` (`src/lib/ai/knowledgeTools.ts`), каждый — отдельный шаг и блок ленты, запись в `tool_runs` у вошедшего:
  - «Отели по характеристикам» — отбор отелей городов плана по claims: самая громкая ночная полоса EEA ниже порога, оценка дня, высота здания; отели без данных — «нет данных», а не «подходит/не подходит»;
  - «Места рядом» (граф хранилища) — ближайшее место категории по связям `near` с claim расстояния, уверенностью и источником OSM или Островка; нет связи — «в данных нет»;
  - «Отзывы» (поиск по отзывам) — фрагменты отзывов по теме для подобранных отелей, цитата, уверенность 0,75, источник.
- Индексы для отбора по всем отелям сразу (`src/lib/db/knowledge.ts`): уровни шума и высоты, места категории по `near`, claims по id — анонимным ключом, в кэше каталога.
- Выбор вызовов (`src/lib/ai/knowledgeTurn.ts`): модель через tool calling (AI SDK) выбирает инструменты и параметры (порог шума, категория, радиус, тема), пока идёт поиск по смыслу; без модели или по таймауту — правила по словам пожелания (аптека, тихо, отзывы о …). Отели, с которыми согласны все вызовы, отбираются по индексам; затем вызовы выполняются параллельно, каждый — независимый запуск.
- Ответ: текст правилами только из claims запусков (значение, источник, уверенность) по каждому отелю, честное «нет данных», неудавшиеся инструменты названы; модель может добавить одну фразу-вывод, если она проходит проверки `checkedRemark` (без чисел и чужих имён). Слова отзывов модели не передаются. Новое поле ответа `findings`; карточки плана — подобранные отели.
- Контракт: необязательные группы `groups` (характеристики по отелю с вердиктом); `fitResult` держит группы согласованными при урезании. `ToolRunCard` показывает раздел «По отелям»: первые три, остальные — по кнопке «Показать все».
- Шаг характеристик (`featuresStep`) не дублирует «тихо», когда его отбирают инструменты хранилища.
- OpenAPI: поле `findings`, группы в `ToolRun`, пример ответа подбора. `docs/tools.md`: инструменты подбора и группы.

Не меняются: схема базы, страницы отеля, бронирование, маршруты `src/app/api/hotels/**`, вопросы брифа (подбор начинается, когда бриф полный, как прежде).
