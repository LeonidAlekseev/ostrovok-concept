## Why

Этап A2 Travel OS (95а): каталог читается из Supabase, а не из кода. Следующие changes добавят в базу хостелы, апартаменты, виллы (`catalog-stay-types`) и отели, созданные моделью для демо-маршрутов (`generate-demo-routes`) — их нет в генераторе, поэтому интерфейс должен брать данные из базы. После `catalog-pure-functions` весь доступ идёт через `src/lib/catalogSource.ts`.

## What Changes

- Серверный слой `src/lib/db/catalog.ts` (`server-only`): чтение `destinations` и `hotels` через Supabase (anon-ключ, RLS чтения уже есть), кеш Next 16 с тегом `catalog` и временем жизни; ошибка базы — понятная ошибка/`notFound`, без падения страницы.
- Страницы и серверные компоненты читают каталог на сервере: главная, `/search`, `/hotels/[hotelId]`, `/hotels/[hotelId]/rooms`, бронь, подтверждение, поездки, избранное. Клиентским компонентам — только нужные данные пропсами (сводки отелей направления, нужные полные отели), не весь каталог.
- `GET /api/hotels?ids=` — полные или сводные отели по списку `id` для мест, где `id` известны только в браузере (избранное, поездки из `localStorage`); ограничение числа `id`, кеш.
- `generateStaticParams` страниц отеля — из базы; страницы новых отелей открываются без пересборки (динамические параметры + кеш).
- Генератор `src/lib/catalog.ts` остаётся источником `db:seed` и фикстурой тестов; в клиентский бандл генератор не попадает.
- Обновление кеша после `db:seed`: защищённый маршрут ревалидации тега `catalog` (секрет из `getSecret`) или короткое время жизни — решение в design.
- README: «каталог в Supabase; после изменения данных — `npm run db:seed` и ревалидация».

## Impact

`src/lib/db/catalog.ts`, `src/lib/catalogSource.ts`, `src/app/**`, `src/app/api/hotels/route.ts`, клиентские компоненты каталога, тесты (моки слоя данных), README. Спека `hotel-catalog`.
