## Context

Шум отеля для страницы и Эвала собирается на лету: `hotel_geo` (полосы EEA END 2022 по слоям), `osm_places_near` (шумные места в 200 м), `dayEstimate` (Lday по 2002/49/EC с допущением «вечер = день»). Отзывы гостей лежат в `ota_hotel_pages.reviews->'list'` (576 отзывов у 98 отелей; у 19 нет текста — только оценка). У источников разные ключи: `ota-<master_id>`, `node/123`, id отзыва, id набора данных. Следующий change (`tool-run-contract`) построит на этой базе общий `ToolResult` и инструмент «Анализ шума»; здесь — только схема, заполнение и чтение. Решения пользователя: 1а 2а 3а 4а 5а (одна миграция, `hotel_features` и поиск не трогаем, векторы позже, `tool_runs` сейчас, заполнение в `db:features`).

## Goals / Non-Goals

**Goals:** у каждого значения — сущность, типизированное значение, эпистемический статус, доказательства, расчёт для производных; противоречия — отдельные строки; отзывы — документы с полнотекстовым поиском; повторный запуск ничего не дублирует; RLS как у каталога и чатов.

**Non-Goals:** векторы фрагментов (колонка есть, пустая), инструмент «Анализ шума», запись `tool_runs`, UI, механизм ожидания ответа отельера, звукоизоляция зданий и любое «снижение децибел», вывод «тихо/шумно» из отзывов, изменение `hotel_features` и поиска.

## Decisions

### Реестр `entities` с `unique(kind, ref)`
`claims` и `relations` ссылаются FK на одну таблицу вместо полиморфных пар «тип + текстовый ключ». `ref` — исходный ключ как есть (`ota-1`, `node/123`), `hotel_id` — FK на `hotels` для отеля и его номеров (CHECK: у отеля `hotel_id = ref`). Виды: `hotel`, `building`, `room`, `osm_place`, `ota_poi`; сейчас заполняются `hotel` и `osm_place`. Связь «отель → здание» не заполняется: `hotel_geo` берёт ближайшее здание в 50 м, это не «located_in».

### Значение утверждения — типизированные колонки, диапазон — `value_min`/`value_max`
Колонки `value_numeric`, `value_min`/`value_max`, `value_text`, `value_boolean`, `value_json`; CHECK: заполнен ровно один вид (диапазон считается одним видом, если задана хотя бы одна граница), `value_min <= value_max`. Полоса EEA — диапазон с открытым концом: «ниже 40 дБ» — `null–39`, «от 75 дБ» — `75–null`; две отдельные claim на нижнюю и верхнюю границу развалили бы одну полосу на два факта без связи. `value_json` оставлен на редкие структуры, всё числовое — в колонках с индексами `(property, value_numeric)` и `(property, value_min, value_max)`. Счёт «20 и больше» (предел ответа `osm_places_near`) — диапазон `20–null`, а не число 20.

### Свойства и ключ источника
`property` — стабильный идентификатор через точку (CHECK по шаблону): `noise.lden.<слой EEA>`, `noise.lnight.<слой>`, `noise.lday.estimate.<слой>`, `noise.nearby.distance`, `noise.nearby.<категория>.count`, `noise.review.mention`. Слои — имена EEA как есть (`roadsInAgglomeration`). `source_key` различает утверждения одной сущности и свойства (элемент OSM, `id:часть:номер предложения` отзыва) и вместе с ними — естественный ключ `unique(entity_id, property, source_key)` для идемпотентной записи. Противоречащие утверждения из разных источников получают разные `source_key` и остаются отдельными строками.

### Эпистемический статус и confidence
`reported` — так говорит источник (карта EEA, гость), `derived` — вычислено (CHECK: у `derived` есть `calculation_id`), `observed` и `inferred` — на будущее (измерение, вывод модели). `confidence` везде NULL: ни у EEA (полоса без погрешности), ни у OSM, ни у отзывов нет основания для числа. Ограничения — `limitations text[]` у утверждения и у расчёта.

### Расчёты отдельно, с ключом
`calculations(key unique, method, version, inputs, parameters, limitations, computed_at)`. Ключ — `noise.lday:<отель>:<слой>`, `noise.nearby:<отель>`: новый прогон с другими входами обновляет расчёт на месте, а не плодит копии. Lday: метод 2002/49/EC (приложение I), версия `dayEstimate-1`, входы — обе полосы слоя, параметры — часы и поправки периодов и оба допущения («вечер = день», «день не тише ночи»). Расстояния и счёт мест — один расчёт `osm_places_near` на отель (радиус, предел на категорию, категории).

### Доказательства
`evidence(type, title, provider, external_id, url, retrieved_at, excerpt, metadata, dataset_id)`, `unique(provider, external_id)`. Набор EEA — одна строка (`dataset_id` FK на `geo_datasets`, url набора, `retrieved_at` = `loaded_at`); элемент OSM — строка на элемент (`url` openstreetmap.org, `retrieved_at` = `fetched_at` кэша, атрибуция ODbL в metadata); отзыв — строка на отзыв (provider «Островок», `external_id` = id отзыва, `retrieved_at` = `updated_at` снимка страницы, `url` NULL — ссылки на отзыв в снимке нет). `claim_evidence.role`: `source` — утверждение передаёт источник, `input` — источник вошёл в расчёт. Имя и номер автора отзыва не копируются.

### Документы и фрагменты: русский стеммер
Документ — отзыв целиком (заголовок, текст, «понравилось», «не понравилось» через пустую строку), один на доказательство (`unique(evidence_id)`), `language = 'ru'` при кириллице, иначе NULL. Фрагмент — часть отзыва (длинная режется по предложениям до 2000 символов), `fts` — `to_tsvector('russian', text)` generated stored, GIN. `russian`, а не `simple`: отзывы русские, стеммер сводит «шума/шумом/шуме» и «тишина/тишины»; латиница уходит в английский стеммер. Ограничение Snowball: «шумно» и «шум» дают разные основы, запрос «шум | шумно» находит оба. `embedding halfvec(2048)` NULL до этапа векторов; при смене текста фрагмента скрипт обнуляет вектор. Поиск — `hotel_chunks_search(hotel_id, query, max_rows ≤ 50)`: `websearch_to_tsquery`, `ts_rank`, `security invoker` (фрагменты и так публичны). Отзывы — недоверенный текст: хранится как данные, читатель цитирует, не исполняет.

### Упоминания шума в отзывах
Предложение части отзыва со словом из `NOISE_MENTION` (шум-, тих-, тиш-, громк-, звукоизол-, слышн-, слышимост-, noise/quiet/loud, с «не»/«бес» и без букв перед словом — «стихи» не в счёт) даёт `noise.review.mention`: `reported`, значение — само предложение (до 300 символов вокруг слова), `observed_at` — дата отзыва (дата проживания есть не у всех). Тон не определяется: «тихо» и «шумно» не выводятся. Отзыв без таких слов не даёт утверждения — отсутствие упоминаний не значит «тихо».

### Запись: естественные ключи, только своя часть
`scripts/lib/claims-store.ts` по порядку FK пишет сущности, доказательства, расчёты, утверждения, связи с доказательствами, связи, документы, фрагменты: читает текущие строки своей части (виды `hotel`/`osm_place`, провайдеры EEA/OpenStreetMap/Островок, свойства и ключи расчётов `noise.*`, предикат `near`, документы `review`), сравнивает по значениям (время — как момент, JSON — без порядка ключей), upsert только новых и изменённых, удаляет устаревшие в обратном порядке после всех записей (устаревшее утверждение держит устаревший расчёт по FK `restrict`). Остальные строки таблиц не трогаются — их может писать следующий change.

### `tool_runs`
Как `assistant_messages`: `(chat_id, user_id)` → `assistant_chats(id, user_id) on delete cascade`, RLS только владелец (select/insert/update/delete для authenticated), anon без прав. `message_id` без FK: id сообщения создаёт браузер, и сообщение может сохраниться позже запуска. CHECK: `completed_at` есть ровно у `success`/`error`, `error` — ровно у `error`, `resume` — только у `waiting`; `result_data` ≤ 100 000 байт, `error` и `resume` ≤ 10 000. Доказательства запуска — `tool_run_evidence(tool_run_id, user_id, evidence_id)` с FK на запуск того же пользователя вместо `uuid[]`: целостность ссылок и та же RLS по `user_id`.

### RLS справочника
`entities`, `claims`, `evidence`, `claim_evidence`, `calculations`, `relations`, `documents`, `document_chunks`: политика select для anon и authenticated, `revoke all` + `grant select`; пишет service role (обходит RLS). Как `hotel_features`: каталог публичен. Функций `security definer` нет.

## Risks / Trade-offs

- Подстрочный поиск слов о шуме даёт и упоминания вроде «тихий центр» — это всё равно слово о тишине; утверждение — цитата, а не вывод, так что ложного вывода нет.
- `hotel_geo` даёт одну (громкую) полосу на слой и индикатор: соседние полосы у границы контура не хранятся.
- Счёт мест ограничен ответом `osm_places_near` (20 на категорию) и полнотой OSM; это записано в ограничениях расчёта.
- Документы отзывов публичны, как страница отеля; автор не копируется.
