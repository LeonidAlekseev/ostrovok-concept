## Why

После защит #293 тест «keeps every chat after a reload» снова упал в CI (PR #298, run 40297977561, 2026-10-26 09:16) и на этот раз вывел хранилище: один чат «к морю» с сообщениями `user: к морю` → `assistant: Записал…` → `user: к морю` → `assistant: Записал…`. Пользователь ввёл сообщение один раз, а в чат оно попало дважды и получило два ответа. Ранее (2026-10-26 07:54) у двух копий были разные id и одинаковый `createdAt` до миллисекунды. Защита `send` через `chatsRef` (#293) этот путь не перекрывает — значит, вторая копия появляется в обход `send` или в другом экземпляре состояния (загрузка/слияние чатов, миграция старого диалога, второй экземпляр хука). Лог: `/tmp/duplicate-send-ci-3.txt`.

## What Changes

- Найти путь, по которому сообщение пользователя появляется в чате дважды, и устранить его; одно сообщение — один ответ.
- Временная диагностика допустима только в ветке для поиска причины (например, стек вызова `send`/слияния при дубле, многократные прогоны CI в ветке); в итоговый PR — только исправление и падающий без него тест.

## Impact

- Спецификация `assistant-search`, требование «Один ответ на сообщение» — сценарий для одного ввода.
- Код: `src/components/AssistantPage/useChats.ts`, `AssistantSearch.tsx`, загрузка/слияние чатов (`src/lib/assistantChats*.ts`) — по результату разбора; тесты.
