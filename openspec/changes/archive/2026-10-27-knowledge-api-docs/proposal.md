## Why

Хранилище знаний (утверждения с источниками, отзывы с полнотекстовым поиском, связи отеля с местами) доступно только серверному коду и инструментам Эвала. Внешний разработчик и сам Эвал-клиент не могут прочитать то, что Эвал знает об отеле, вместе с источниками и расчётами, а страница `/api/docs` об этом молчит.

## What Changes

- Три публичных маршрута только для чтения, с ключом anon и кэшем CDN как у соседей, только для настоящих видимых отелей (иначе 404), с проверкой входа zod и ошибками через `apiError`:
  - `GET /api/hotels/{hotelId}/claims?property=&limit=` — утверждения по префиксу свойства со значением, единицей, статусом, уверенностью, источниками и расчётом; размер ответа ограничен `limit` (по умолчанию 100, не больше 200) и признаком `truncated`.
  - `GET /api/hotels/{hotelId}/documents/search?q=&limit=` — фрагменты отзывов по полнотекстовому поиску `hotel_chunks_search` с рангом и источником; запрос не подменяется, ограничение русского стеммера («шум» ≠ «шумно») описано в документации; отзывы отдаются как недоверенные данные.
  - `GET /api/hotels/{hotelId}/relations?predicate=&category=&limit=` — связи отеля (`near`, `nearest_building`): объект с координатами и категориями, расстояние как утверждение с уверенностью, источник, уверенность связи.
- `src/lib/db/knowledge.ts`: чтение связей отеля; координаты и категории мест берутся из кэша OSM (`osm_places_near`), потому что в хранилище их нет.
- Документ OpenAPI: тег «Знания об отеле», три операции с живыми примерами (ota-9096882; для отзывов ota-7857547), «Try it», карта мест на `/api/docs` для `relations`.
