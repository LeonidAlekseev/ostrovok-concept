## MODIFIED Requirements

### Requirement: Страница документации
Страница `/api/docs` SHALL показывать интерактивную документацию обоих документов с выполнением запросов («Try it») против текущего окружения, во всех окружениях. Ответ гео-маршрута (отели, вид, здания, шум, карта Эвала) SHALL показываться на карте рядом с ответом; пример ответа гео-маршрута SHALL показываться на карте без запроса. Места виджета ответа Эвала (`view`: места с вердиктами и линиями от отеля; `noise`: шумные места) SHALL тоже показываться на карте; виджет без мест карты не даёт. Страница SHALL работать без горизонтального скролла на 375 и 1280 px.

#### Scenario: Try it с картой
- **WHEN** разработчик выполняет `GET /api/hotels/ota-7481548/noise-map` на `/api/docs`
- **THEN** рядом с ответом карта показывает полигоны шума вокруг отеля

#### Scenario: Пример на карте
- **WHEN** разработчик выбирает «Пример на карте» для вида из отеля
- **THEN** карта показывает отель, лучи и цели примера

#### Scenario: Пример виджета вида
- **WHEN** разработчик выбирает пример «ТЦ Aqua с 9-го этажа» ответа Эвала
- **THEN** карта показывает отель, место с цветом вердикта и линию до него

### Requirement: Запуск инструмента в ответе ассистента
Схема `POST /api/assistant` SHALL описывать `chatId` и `messageId` запроса и компонент `ToolRun` в шагах ответа (id запуска и результат контракта с источниками, характеристиками, расчётами, ограничениями и ошибкой); пример ответа о шуме для ota-7481548 SHALL проходить проверку по схеме.

#### Scenario: Пример о шуме
- **WHEN** тест документа проверяет примеры
- **THEN** ответ о шуме с шагом «Анализ шума» и его `run` соответствует схеме

### Requirement: Знания об отеле в документе OpenAPI
Три маршрута SHALL быть описаны в документе OpenAPI под тегом «Знания об отеле»: схемы из zod рядом с маршрутами, описание на русском, живые примеры ответов (ota-7481548; для отзывов ota-7857547 с запросом, который находит фрагменты, и ota-7568446 с запросом по смыслу, который находит слова отельера). Сведения отельера (`GET /api/hotels/{hotelId}/hotelier/facts`) SHALL иметь живой пример. Страница `/api/docs` SHALL показывать места ответа `relations` на карте.

#### Scenario: Пример на карте
- **WHEN** разработчик открывает пример ответа `relations`
- **THEN** карта рисует места с названием и расстоянием и маркер отеля

## ADDED Requirements

### Requirement: Виды запросов к Эвалу в документе OpenAPI
Описание `POST /api/assistant` SHALL разделять вопрос об отеле (`brief.hotelId`: места рядом, маршруты пешком и на машине, `geocode` по названию после «до …», вид из окон и с этажа, шум, отзывы и сведения отельера, доступность и запрос отельеру), подбор (по описанию, по фото через `match_hotel_photos`, по характеристикам хранилища и отзывам) и бронирования, и называть то, чего у подбора нет (критерии первого этажа и доступности). Примеры SHALL быть живыми ответами маршрута для `ota-7481548` (вид с 9-го этажа — ТЦ Aqua; с 12-го — закат и берег; пеший маршрут; маршрут на машине; «до …»; коляска и первый этаж; отзывы) и подбора (по описанию, по фото) и проходить проверку по схеме. Пример пути к морю (`GET /api/hotels/{hotelId}/view`) SHALL оставаться у `ota-9096882`.

#### Scenario: Вид с этажей
- **WHEN** разработчик открывает примеры запроса к Эвалу
- **THEN** среди них вопрос о ТЦ Aqua с 9-го этажа и о закате и море с 12-го, ответы с виджетом `view`

#### Scenario: Подбор по фото
- **WHEN** разработчик открывает пример подбора по фото
- **THEN** запрос содержит `photos` (data URL), ответ — шаг поиска по фото, `photo.action = similar` и отели `matches`
