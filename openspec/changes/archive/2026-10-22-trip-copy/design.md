## Решения

- **Снимок.** Копия хранит полный снимок маршрута на момент копирования (точки, трансферы, досуг, порядок) + правки пользователя; изменение исходного маршрута копию не меняет. Расчёты — из `src/lib/routes.ts` и `src/lib/ics.ts` (#122), не дублировать.
- **Сохранение.** Правки применяются сразу в интерфейсе и сохраняются серверным действием/route handler с задержкой (debounce ~800 мс); ошибка — сообщение и повтор. Запись — сессией пользователя под RLS (не сервисным ключом). Проверка владельца на сервере.
- **Порядок действий.** День — упорядоченный список узлов. Досуг переставляется перетаскиванием и кнопками «выше/ниже» (доступность с клавиатуры), переносится на другой день меню «Перенести на день N». Заезд, выезд и трансферы привязаны к точкам и не перетаскиваются. Время досуга редактируемо; при переносе время сохраняется.
- **Альтернативы досуга.** Только по нажатию «Предложить другое»: `POST /api/trips/<id>/alternatives` → `nemotron-3.5-lightning` (как `/api/assistant`: `generateObject` + zod, `reasoning.effort: 'none'`, таймаут 8 с, лимит запросов, ответ только кириллицей) → 3 варианта (название, категория, длительность, цена) для города и дня; пользователь выбирает один. Ошибка/таймаут — «Не получилось предложить, попробуйте ещё раз»; ничего не меняется.
- **Замена отеля.** `rankHotelAlternatives(current, candidates, profile?)` — чистая функция: близость типа, звёзд, рейтинга, цены, общие удобства, расстояние до центра; `profile` — точка расширения для эмбеддингов `semantic-search` (в этом change не используется). Окно: список с ценой за ночи точки и разницей «+N ₽ / −N ₽», выбор заменяет отель точки, трансферы пересчитываются.
- **Даты.** Общий компонент выбора даты проекта (без нативного `input type=date`), прошедшие дни недоступны; по умолчанию ближайшие доступные.
- **UI.** Только Tailwind + shadcn; меню — `dropdown-menu` (#122), окна — `dialog`/`sheet`.

## Реализация

- **Данные.** `trips(id uuid, user_id → auth.users, route_id → routes on delete set null, data jsonb ≤ 200 КБ, created_at, updated_at — триггер)`; RLS: select/insert/update/delete только `auth.uid() = user_id`, `anon` без прав. В `data` — `TripData`: снимок `route` + правки `start`, `stops` (отель и ночи), `transfers` (`none` — убран), `leisure` (с `id`, днём и временем). Сохранение (`saveTrip`) берёт `route` из строки базы, от браузера — только правки (zod, число точек и отрезков, отели из каталога и города маршрута). Миграция — `20261022170500_trips.sql`: версия `20261022150000` в базе занята миграцией `semantic-search`.
- **Копия.** `/trip/new?route=<id>`: гостя сервер отправляет на вход с возвратом; вошедшему клиент один раз вызывает серверное действие `copyRouteToTrip` (POST, предзагрузка ссылок копий не создаёт), оно открывает план с заменой адреса.
- **Вход с `next`.** Навигация браузера сразу после действия входа (оно ставит cookie) гонится с перерисовкой страницы Next и обрывается на тяжёлых страницах (карта): `signInDemo(next)` сам делает `redirect(next)`, форма входа перечитывает сессию при закрытии. `@modal/[...catchAll]` закрывает окно входа при переходе на другую страницу.
- **Порядок досуга.** «Выше/ниже» и перетаскивание (HTML5 drag-and-drop, без библиотек) меняют порядок в дне: пункты по очереди занимают времена дня. Время — список с шагом 15 мин (`NativeSelect`), а не `input type=time`: его вид зависит от локали браузера.
- **Замена отеля.** `rankHotelAlternatives(current, candidates, profile?)` в `src/lib/hotelAlternatives.ts`; `profile` — функция похожести отеля на пользователя 0…1 для эмбеддингов. Разница в окне — изменение «Основных» (отель за ночи точки и пересчитанные трансферы).
