## Векторы фрагментов

Инвариант: `content_hash` не пуст ⇔ вектор посчитан по текущему тексту этой моделью. `hotelierKnowledge` уже пишет
так; `claims-store` при изменении фрагмента теперь очищает и `content_hash`, иначе фрагмент с прежним текстом и новыми
метаданными остался бы без вектора навсегда. Скрипт берёт фрагменты, где `content_hash ≠ sha256(модель, размерность,
текст)`, и пишет вектор условием `updated_at` прочитанной строки: фрагмент, переписанный за время запроса к модели,
не получит вектор старого текста.

## Порог близости

Расстояния косинуса у nemotron зависят от длины запроса (минимум по отзывам: «шум» 0,65, развёрнутый вопрос 0,37),
поэтому общий порог не вводится: API отдаёт RRF как раньше, с `ftsPlace`/`vectorPlace`. Инструменты Эвала, которые
выдают фрагмент как утверждение «Отзыв гостя о теме», дополнительно требуют слово темы (`TOPIC_MENTION`,
`NOISE_MENTION`) — близкий только по смыслу фрагмент не цитируется как отзыв о теме.

## Стемминг

До векторов (FTS, весь набор): «шум» — 26 фрагментов, «шумно» — 31; у `ota-7857547` 2 и 5, у `ota-7568446` 0 и 3.
После векторов гибридный поиск (10 строк) по «шум» и по «шумно» дал одинаковые множества фрагментов о шуме у шести
отелей с упоминаниями шума: 7/7, 4/4, 4/4, 3/3, 3/3, 3/3. Встроенные словари Postgres без файлов на сервере
(Supabase) не дают сведения «шумно» к «шум»; префиксный поиск по основам расширил бы запрос в одну сторону и добавил
шум («завтра» в «завтрак»). Поэтому конфигурация FTS не меняется; без ключа модели остаётся прежнее расхождение.
