## Why

Векторы `nvidia/nemotron-3.5-embed-1b` были только у фрагментов сведений отельера: отзывы гостей (1075 фрагментов
97 отелей Валенсии) искались только по словам. Русский стеммер не сводит «шумно» к «шум», поэтому запросы о шуме
находили разное: у отеля `ota-7857547` по «шум» — 2 фрагмента, по «шумно» — 5. Инструменты Эвала «Отзывы» и «Анализ
шума» искали только по словам (`hotel_chunks_search`).

## What Changes

- Скрипт `npm run db:embed:chunks` (`scripts/embed-chunks.ts`) считает векторы всех фрагментов `document_chunks`
  идемпотентно: `content_hash` пишется только вместе с вектором; при изменении фрагмента `npm run db:features`
  очищает и вектор, и `content_hash`.
- API `GET /api/hotels/{id}/documents/search` и `hotel_chunks_hybrid` не меняются: с векторами отзывы находятся и по
  смыслу. Вектор запроса — общий помощник `queryVectorOrNull` (без ключа, при сбое или дольше 4 с — `null`, поиск по
  словам).
- «Отзывы» и «Анализ шума» Эвала ищут гибридно (`searchHotelReviews`): слова темы для полнотекстовой части, название
  темы для части по смыслу; цитируются только фрагменты отзывов, где тема названа словами. `searchHotelChunks`
  удалён; SQL-функция `hotel_chunks_search` остаётся.
- Конфигурация FTS не меняется: в гибридном поиске «шум» и «шумно» дают одинаковые фрагменты о шуме (см. design).

## Impact

- Код: `scripts/embed-chunks.ts`, `scripts/lib/claims-store.ts`, `src/lib/ai/semantic.ts`, `src/lib/db/claims.ts`,
  `src/lib/ai/knowledgeTools.ts`, `src/lib/ai/noiseTool.ts`, маршрут поиска документов.
- Данные: векторы 1075 фрагментов отзывов залиты в существующую колонку `document_chunks.embedding`. Миграций нет.
