# Design

## Context

Мотивация — в proposal.md. Текущее состояние, которое определяет подход (проверено по коду):

- `DestinationField` — `role="combobox"` с ручной навигацией `ArrowUp`/`ArrowDown`/`Enter`/`Escape` и `aria-activedescendant`.
- `DateField` и `GuestsField` — кнопка с `aria-haspopup="dialog"`, панель `role="dialog"`, закрытие через `useDismiss` (клик вне и `Escape`). После выбора второй даты `DateField` закрывает поповер и возвращает фокус на кнопку.
- `Calendar` — сетка с roving `tabIndex`, стрелки, `PageUp`/`PageDown`, `group` на каждый месяц.
- `Header` — две панели (`role="dialog"`) с общим `useDismiss`, одна открыта за раз.
- `SearchPanel` — `role="tablist"`, стрелки `ArrowLeft`/`ArrowRight` и `Home`/`End`, `aria-controls`.
- `RandomSearch` — `role="radiogroup"` поверх обычных `<button role="radio">`. Стрелок нет, каждый знак достижим `Tab`.
- Base UI (`@base-ui/react` ^1.9.0) объявлен в `package.json`, в проекте ещё не используется.

## Goals / Non-Goals

**Goals:**
- Клавиатурная логика и ARIA для combobox, поповеров, вкладок и radiogroup отдаётся Base UI, ручная логика удаляется.
- Роли, подписи и связки `aria-*` совпадают с текущими (кроме явно указанного в spec для radiogroup).
- Визуал по токенам и примитивам `design-system`.

**Non-Goals:**
- Доменная графика: глобус, пины, карточка на глобусе, слот-машина — не трогаем.
- Смена данных, API и текстов.
- Новые виджеты (меню, тултипы) сверх текущих.

## Decisions

### D1. Base UI как основа, shadcn-обёртки в `src/components/ui/`

Для каждого виджета создаётся обёртка в `src/components/ui/` (`combobox.tsx`, `popover.tsx`, `tabs.tsx`, `radio-group.tsx`) по шаблону shadcn на Base UI: классы через `cn()`, варианты через `cva` при необходимости. Доменные компоненты импортируют обёртки, а не `@base-ui/react` напрямую. Это следует правилу design-system D2: Base UI отвечает за поведение, Tailwind — за вид.

Альтернатива: импортировать `@base-ui/react` прямо в доменных файлах. Отклонена: тогда каждый виджет дублирует классы и стили.

### D2. Поповеры: Base UI Popover на всех трёх местах

`DateField`, `GuestsField` и `Header` переводятся на `Popover` (Root, Trigger, Portal, Positioner, Popup). Base UI закрывает по `Escape` и клику вне, возвращает фокус на триггер и выставляет `aria-expanded`/`aria-controls`. Ручной `useDismiss` удаляется, если после переноса вызовов не осталось; проверка по grep.

Панель шапки с двумя взаимоисключающими панелями: состояние `open: Panel | null` остаётся, но открытие управляется через `open`/`onOpenChange` двух поповеров. Одновременно открыт один — правило выполняется через контролируемое состояние, а не через ручное закрытие второго.

Риск: порталы Base UI меняют DOM-позицию панели и селекторы в CSS Modules (`.months` и т.п. внутри поповера). Модули поповера переезжают вместе с компонентом; проверяется визуально.

### D3. Календарь: сохраняем свою клавиатурную модель

Base UI не даёт range-календаря с roving focus по дням. Поэтому `Calendar` остаётся собственной сеткой. Меняется только обёртка: кнопки навигации по месяцам уже на `Button`, а сам поповер — из D2. Логика `onKeyDown`, `focused`, `view` не переписывается, это поведение описано в spec и уже работает.

Альтернатива: перейти на библиотеку календарей. Отклонена: вне scope change и добавляет зависимость ради одного виджета.

### D4. Combobox направления

`DestinationField` переводится на Base UI `Combobox` (Root, Input, Trigger при необходимости, Portal, Positioner, Popup, List, Item). Фильтрация и источник подсказок остаются прежними: Base UI не должен менять набор вариантов, только выводить их. Пункты получают `role="option"`, список `role="listbox"` — из Base UI.

Риск: Base UI по умолчанию очищает или выбирает значение при потере фокуса. Поведение при `blur` и `Escape` сверяется со spec; если расходится, задаётся явно.

### D5. Вкладки

`SearchPanel` переводится на Base UI `Tabs` (Root, List, Tab, Panel). Режим поиска остаётся в родительском состоянии: `value` и `onValueChange` привязаны к `mode`. Роли, `id` и `aria-controls` генерирует Base UI; подпись `Способ поиска` передаётся на `Tabs.List`. Ручные `tabRefs` и `onKeyDown` удаляются.

### D6. Radiogroup знаков зодиака

`RandomSearch` переводится на Base UI `RadioGroup` и `Radio`. Это единственное место, где клавиатурное поведение меняется сознательно: стрелки перемещают выбор, один `Tab` проходит группу. Причина — иначе группа не соответствует своей роли. Изменение отмечено в spec и в proposal. Подпись `legend` остаётся в `fieldset`.

### D7. Визуал

Каждый виджет получает классы из примитивов через `cn()`. Состояния (`data-[checked]`, `data-[highlighted]`, `data-[selected]`, `data-[disabled]`) — из Base UI через `data-*`-селекторы Tailwind. Модульные классы остаются только для раскладки (как в design-system D2). Фокус — глобальный `:focus-visible` из `@layer base` (design-system D4).

## Risks / Trade-offs

- [Base UI меняет фокус и закрытие поповеров] → Сценарии spec проверяются вручную в браузере (клавиатура и мышь) после каждого перевода; каждый виджет — отдельный коммит.
- [Порталы выносят панели из `.months`/модульной разметки] → Проверка CSS-селекторов после переноса; при необходимости модуль поповера передаётся через `className` (раскладка).
- [Combobox меняет поведение blur/Escape] → Явная настройка, сверка со spec.
- [Radiogroup получает стрелки — новое поведение] → Отмечено в spec, согласовать с владельцем продукта до мерджа.

## Migration Plan

Порядок от простого к сложному: Tabs → RadioGroup → Popover (Header, Guests, Date) → Combobox. Каждый виджет — отдельный коммит: перевод, проверка `npm run typecheck`, `npm run lint`, `npm run build`, ручная сверка сценариев. Откат — `git revert` коммита виджета. Данных и API change не касается.

После Popover-переноса удаляется `useDismiss`, если не осталось вызовов; это отдельный коммит в конце.

## Результаты проверки

Сверка с эталоном (коммит до переноса) на 375, 768 и 1280 px: вкладки и сетка знаков совпадают пиксель в пиксель; поповеры, список направления и шапка совпадают с точностью до субпикселя. Остаются расхождения:

- Панели «Избранное» и «Уведомления» выравниваются по своей кнопке, а не по правому краю группы (Base UI не принимает внешний якорь). Панель «Меню» на прежнем месте.
- При открытом списке направления Base UI ставит `aria-hidden` на остальной документ (`FloatingFocusManager`, текстовый комбобокс без модальности). Вкладки и поля пропадают из дерева доступности, пока открыт список; при закрытии возвращаются. Роли при этом сохраняются.
- Сценарии клавиатуры и мыши проверены скриптом по каждому виджету (вкладки, radiogroup, шапка, гости, даты, направление); визуальный индикатор фокуса на вкладке не сверялся отдельно.
