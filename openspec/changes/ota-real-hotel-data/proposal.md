## Why
Решения пользователя 2026-10-24 (ответы 2а, 3а): у настоящих отелей Валенсии (`ota-*`) должны быть только данные Островка.
- Сейчас маппер `src/lib/ota/hotel.ts` (~строка 100–125) собирает номера только из тарифов выдачи, и у отеля в каталоге часто один номер, хотя типов номеров (`static_vm.room_groups`) в среднем около 18. Эвал (`assistant-chat-redesign`) называет номера с видом, которых на странице отеля нет.
- У оценённых отелей генератор каталога дописывает сгенерированные отзывы, оценки по разделам и фото гостей (`src/lib/ota/hotel.ts:22`, `:194`), и отзывы попадают в текст для поиска по смыслу (`src/lib/ai/documents.ts:45-47`). Пользователь добывает настоящие данные страниц отелей у Островка; до тех пор сгенерированных отзывов у настоящих отелей быть не должно.

## What Changes
- **Все типы номеров** из `static_vm.room_groups`: номер с тарифами выдачи — как сейчас, с ценами; тип номера без тарифа — без цены и бронирования, с пометкой «Нет цены на выбранные даты». Фото, площадь, кровати — из данных Островка, если есть.
- **Без сгенерированных отзывов** у `ota-*`: нет сгенерированных отзывов, оценок по разделам и фото гостей; рейтинг и число отзывов — настоящие из данных Островка. Блок отзывов на странице отеля показывает рейтинг и «Отзывы появятся позже» без списка; в текст для поиска по смыслу отзывы `ota-*` не попадают.
- **Данные в базе:** `public.hotels` для `ota-*` пересобираются из `public.ota_hotels` (сырые данные уже в базе) идемпотентным скриптом, без исходного JSON; затем `db:embed`. Запись в боевую базу выполняет пользователь (классификатор запрещает агентам), исполнитель готовит команды и проверяет `--dry-run`.
- Синтетические отели не меняются.

## Impact
- `src/lib/ota/hotel.ts`, `scripts/seed-valencia.ts` (или новый режим пересборки из `ota_hotels`), `src/lib/ai/documents.ts`, компоненты номеров и отзывов страницы отеля, тесты. Spec `hotel-catalog`.
